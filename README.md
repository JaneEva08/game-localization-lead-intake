# VPk01.1 — регистрация входящих предложений игровых проектов

Локальный MVP для сотрудников компании, рассматривающей входящие предложения разработчиков игр о сотрудничестве по локализации. Сотрудник фиксирует контакт и игру через веб-форму; `POST /lead` проверяет JSON, сохраняет отдельную карточку для каждой игры в SQLite и записывает событие `New lead saved: <id>` в таблицу `events`. Публичной формы для самостоятельной отправки разработчиком в MVP нет.

## Запуск

Требуется Python 3.10 или новее.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python app.py
```

Сервис слушает `http://127.0.0.1:5000`. При запуске создаётся `data/leads.sqlite3`. Также базу можно подготовить командой `flask --app app init-db`.

Проверки выполнялись на Flask test client с отдельной временной SQLite-базой. Проверены мульти-игровая запись, фильтрация, категории и ошибки ввода/БД. Подробности — в [report.md](report.md).

Скриншоты демонстрации интерфейса и мобильной раскладки находятся в [screenshots/](screenshots/).

## Пример запроса

```powershell
$body = @{
  name = "Test Contact One"
  contact = "contact-one@example.test"
  source = "developer_email"
  comment = "A fictional studio is considering Russian localization for a strategy game."
  company = "Example Studio One"
  games = @(@{ title = "Example Strategy"; url = "https://example.test/game-one"; notes = "PC; strategy" }, @{ title = "Example Adventure"; url = ""; notes = "Mobile" })
} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:5000/lead -ContentType "application/json" -Body $body
```

Обязательные поля по учебному заданию: `name`, `contact`, `source`, `comment`. Компания необязательна. `games` — непустой список объектов игры с обязательным `title`; для каждой игры можно передать `url`, ссылку на материалы (`materials_url`), заметки и категории жанров, платформ и языков. Для данного MVP рассматривается сценарий входящего предложения. API также принимает дополнительное поле направления для совместимости интерфейса. API возвращает HTTP 201 и ID созданных карточек. Невалидный JSON, отсутствующее поле или неверный тип получают HTTP 400. Ошибки SQLite получают HTTP 500, подробности записываются в лог сервера.

## Данные

Таблица `leads` хранит карточки игр: общие контакт и компания повторяются для связи с каждой игрой; у каждой карточки свой ID и статус. Таблица `events` — подтверждение её приёма. Запись заявки и события выполняется одной транзакцией. Путь к базе можно изменить переменной `DATABASE_PATH`; файл базы исключён из Git.

В [payloads.json](payloads.json) лежат демонстрационные примеры, использующие фиктивные контакты и домен `.test`.

## Границы MVP

Это учебный локальный прототип: нет публичной формы для разработчика, авторизации, внешнего развёртывания, LLM, отправки писем и автоматического сбора сведений. Запрос due diligence, LLM-анализ, пакет для инвесторов и маркетологов, экспертные заключения и итоговый статус относятся к следующим этапам плана.


## Библиотека категорий и поиск

Жанры, платформы и языки поддерживаются в отдельной библиотеке. В каждой карточке можно отметить несколько значений в компактном выпадающем списке. В списке игр доступны поиск и фильтры по направлению, статусу, жанру, платформе и языку.


## Проверка журнала событий

Из PowerShell в папке проекта можно вывести последние события командой: python -c "import sqlite3; print(sqlite3.connect('data/leads.sqlite3').execute('SELECT id, created_at, message FROM events ORDER BY id DESC LIMIT 10').fetchall())"

Успешная запись фиксирует событие в точном формате New lead saved: <id>.
